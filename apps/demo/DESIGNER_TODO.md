# Avalanche Bakery 디자인 수정 요청서

## 이번 라운드의 목적

현재 화면은 기능과 상태 전환은 동작하지만, 일부 오브젝트가 깨져 보이고 전체 인상이 단조롭다. 다음 개발 라운드 전에 디자이너가 시각 구조와 정확한 수치를 확정한다.

이번 라운드에서 개발자는 화면 CSS를 임의로 보정하지 않는다. 디자이너 결정이 `DESIGN.md`에 반영되면 그 값을 그대로 구현한다.

## 현재 확인된 파손

### 1. 작업대 빈 상태 그림

- `첫 쿠키 사진을 기다려요` 위의 믹싱볼과 도구가 하나의 사물로 보이지 않는다.
- CSS 테두리와 회전선으로 만든 도형이 축소될 때 서로 떨어져 보여 깨진 아이콘처럼 보인다.
- 디자이너는 최종 모양을 인라인 SVG 또는 재현 가능한 벡터 수치로 제공한다.
- 필요한 값: 전체 크기, 선 굵기, 각 path 또는 좌표, 문구와의 간격, 1920×1080 기준 위치.

### 2. 오븐 내부

- 준비 문구, 열기 세로선, 카드 영역과 선반이 같은 공간에서 안정적으로 겹치지 않는다.
- 현재 CSS Grid 자동 배치 때문에 일부 레이어가 암묵적 열로 밀려나며, 열기 선이 한쪽에 붙거나 일부만 보인다.
- 카드가 들어오면 준비 문구·열기·카드의 위계가 불명확해진다.
- 디자이너는 빈 상태와 굽는 상태를 각각 한 장의 정지 시안으로 확정한다.
- 필요한 값: 오븐 창 내부 좌표, 카드 크기, 준비 문구 위치, 열기 선 3개의 x/y/높이, 선반 위치, 각 레이어의 앞뒤 순서.

### 3. 작업대의 카드가 1~3장일 때

- 현재는 항상 3열 그리드를 사용해 카드가 한 장뿐이어도 지나치게 작다.
- 3~5m 거리와 `/demo` 축소 화면에서 사진과 닉네임이 사건의 주인공으로 읽히지 않는다.
- 디자이너는 수량별 배치 규칙을 확정한다.

| 수량 | 확정할 값 |
| --- | --- |
| 1장 | 카드 너비·높이, 정렬 위치 |
| 2~3장 | 열 수, 카드 크기, 간격 |
| 4~6장 | 열 수, 카드 크기, 간격 |
| 7~15장 | 축소 규칙과 감춰도 되는 정보 |

카드 크기가 상태 전환 중 바뀌어도 동일한 `layoutId` 이동이 자연스럽게 이어져야 한다.

### 4. 최종 서체

- 현재 시스템 대체 글꼴은 OS마다 한글 글자 폭과 굵기가 달라 줄바꿈 결과가 달라진다.
- `/styleguide`의 A/B/C 중 최종 조합을 하나 선택하고 나머지 폰트는 제거한다.
- Latin과 한글을 모두 지정한다. 제목용과 작은 라벨용 두 계열만 사용한다.
- 필요한 값: 폰트 이름, weight, 각 타이포 단계의 px/line-height/letter-spacing.

### 5. 단조로운 화면의 위계

색을 추가하지 않고 아래 상태마다 시선의 1순위를 하나씩 정한다.

| 상태 | 현재 문제 | 디자이너가 정할 것 |
| --- | --- | --- |
| 빈 화면 | 종이색 박스가 반복되어 미완성 와이어프레임처럼 보임 | 작업대·오븐·진열장의 재질 차이와 첫 시선 |
| 사진 도착 | 작은 카드가 넓은 작업대에 고립됨 | 카드 주변의 면적 배분과 정보 위계 |
| 굽는 중 | 오븐 안 요소가 서로 경쟁함 | 카드·열·문구 중 1순위와 나머지 감쇠 방식 |
| 진열 도착 | 빈 슬롯 반복이 강해 새 카드가 묻힘 | 목표 슬롯과 기존 슬롯의 명도 차이 |
| 15칸 완료 | 결과가 채워져도 화면의 리듬이 거의 같음 | 외곽 프레임 반응 뒤의 최종 정지 모습 |

허용된 팔레트는 `--ava`, `--ember`, `--paper`, `--ink`, `--gold` 다섯 색뿐이다. 새 색, 회색, 흰색, 장식용 그라데이션은 추가하지 않는다.

## 폰 화면에서 확정할 것

- A안의 `당신의 쿠키를 굽고 있어요`와 `고개를 들어 앞 화면을 보세요`의 고정 줄바꿈.
- B안 네 단계에서 제목과 설명의 크기·간격. TV를 봐야 하는 순간에는 폰 정보가 시선을 빼앗지 않아야 한다.
- C안 대기 문구, 운영자 안내 박스, `오븐에 넣기` 버튼의 수직 간격.
- 완료 화면의 증서 크기와 `#tokenId` 위치.
- 기준 화면은 390×844이며 모든 탭 영역은 최소 56px다.

## 디자이너 산출물

### 1. `DESIGN.md` 업데이트

아래 항목을 설명이 아닌 구현 가능한 값으로 기록한다.

- 최종 폰트 조합과 전체 타이포 토큰
- 작업대 빈 상태 벡터
- 오븐 빈 상태·굽는 상태의 좌표와 레이어 순서
- 작업대 카드 수량별 그리드
- 빈 화면·진행 화면·완료 화면의 시각적 1순위
- 변경되는 border, radius, 간격 값

### 2. 공유용 단일 HTML

권장 파일명은 `avalanche-bakery-review.html`이다.

- 파일을 더블클릭해 `file://`로 열 수 있어야 한다.
- npm, 로컬 서버, 환경변수, API 호출이 없어야 한다.
- CSS와 JavaScript는 한 파일 안에 포함한다.
- 이미지가 필요하면 data URL 또는 인라인 SVG로 포함한다.
- 인터넷이 끊겨도 동일하게 보여야 한다. 웹폰트를 쓴다면 파일에 포함하거나 승인된 fallback을 함께 명시한다.
- 리뷰 전용 조작기는 실제 화면과 분리하고, 한 번에 숨겨 스크린샷을 찍을 수 있어야 한다.
- URL hash 또는 리뷰 조작기로 아래 장면을 바로 열 수 있어야 한다.

필수 장면:

1. `/demo` A/B/C 제출 이후 장면과 완료 장면
2. `/display` 빈 상태
3. 작업대 카드 1장·3장 상태
4. 오븐 카드 1장 상태
5. 진열장 3칸·8칸·15칸 상태
6. 15번째 카드 도착 직후 상태

## 디자인 완료 기준

- 1920×1080에서 믹싱볼과 오븐 내부 요소가 잘리거나 겹치지 않는다.
- 1600×900 `/demo`에서도 폰 문장에 한 글자만 남는 줄이 없다.
- 작업대 카드 한 장의 사진과 닉네임이 3m 거리에서 읽힌다.
- 빈 화면도 베이커리 공간으로 보이며 관리 대시보드나 와이어프레임처럼 보이지 않는다.
- 모든 상태에서 가장 먼저 봐야 할 곳이 한 군데뿐이다.
- 5개 팔레트 밖의 색, 장식용 모션, 파티클, 글래스모피즘이 없다.

## 디자인 확정 뒤 개발 작업

디자이너가 위 산출물을 확정하면 개발자는 다음 순서로 작업한다.

1. 오븐의 암묵적 Grid 배치를 제거하고 명시적 레이어 좌표로 수정
2. 작업대 빈 상태 SVG 교체
3. 수량별 카드 그리드와 최종 폰트 적용
4. `/display`와 `/demo`에 같은 시각 규칙 이식
5. 1920×1080 및 1600×900 전체 상태 캡처 비교
6. 모션·축소 모드·lint·build 회귀 검증
7. 최종 공유용 단일 HTML 생성
