## 임의로 결정한 것과 이유

- `/join` 공통 구간은 이메일 입력과 코드 입력을 별도 화면으로 나누되 둘 다 진행 표시의 `로그인` 한 칸으로 묶었다. 한 화면에 한 행동만 남기면서 전체 과정은 약속한 5단계를 유지하기 위해서다.
- 실기기 카메라가 없는 데스크톱 리뷰에서도 흐름을 확인할 수 있도록 사진 단계에 `샘플 사진으로 보기`를 보조 행동으로 넣었다. 실제 카메라 입력은 `capture="environment"`로 후면 카메라를 우선한다.
- `/join`은 아직 최종 스타일가이드 안이 선택되지 않았으므로 현재 `/display`가 실제로 쓰는 `--display`와 `--mono` 토큰을 그대로 상속한다. 스타일가이드용 여섯 Google 서체는 가져오지 않았다.
- 제출 이후 목업 시간은 A·C 8초, B 10.5초로 정했다. B는 네 단계를 읽을 시간이 더 필요하지만, 세 안 모두 사용자가 별도 조작 없이 짧은 시간 안에 같은 완료 화면에 도착하도록 했다.
- C의 `오븐에 넣기`는 지원 기기에서 45ms 진동을 한 번 요청하고 버튼을 94%로 누른다. 진동을 지원하지 않거나 사용자가 모션을 줄인 환경에서는 상태 전환만으로 동일하게 진행된다.
- `/demo`의 공통 입력은 17초, 제출 이후 비교는 약 11초, 완료 확인은 나머지 시간으로 배분해 전체를 40초 루프로 만들었다. C는 20.5초에 운영자 신호를 가정해 버튼을 누르고, TV의 오븐 진입도 같은 시각에 시작한다.
- `/demo`는 실제 `/display` 스토어를 건드리지 않고 `BakeryScene`에 타임라인으로 만든 `StateResponse`를 직접 전달한다. 따라서 공유 링크를 여러 명이 열어도 서로의 재생 상태에 영향을 주지 않는다.
- 루트 요구사항은 “링크 네 개”라고 적혀 있지만 뒤에 다섯 경로가 명시되어 있어, 누락 위험이 적은 쪽인 다섯 링크(`/demo`, `/join/a`, `/join/b`, `/join/c`, `/display`)를 모두 노출했다.
- 실제 사진이 오기 전에도 이미지 로딩과 크롭을 확인할 수 있도록 15개의 SVG 자리표시자를 만들었다. 15번만 2:3 세로 원본이며 나머지는 정사각형이다. 모두 기존 다섯 색만 쓴다.
- `/styleguide` 비교용 폰트는 `next/font/google`로만 로드한다. A는 `Archivo Black + Gothic A1`, B는 `Oswald + Noto Sans KR`, C는 `Bodoni Moda + Nanum Myeongjo`이며, Latin과 한글의 인상이 함께 갈리도록 짝지었다. 최종안 선택 전까지만 이 여섯 서체를 유지하고 이후 선택받지 못한 두 조합은 제거한다.
- 일반 `/display`의 30초 루프는 참가자를 1.1초 간격으로 넣고, 각 카드를 0.7초 간격으로 준비시킨 뒤 오븐에서 2.1초 머물게 했다. 약 20초에 15칸이 차고 완성 상태를 약 10초 보여준다.
- `?dev=1`은 빈 LIVE 화면에서 시작한다. 운영자가 원하는 수량과 실패 시점을 직접 만들기 쉽고, 세션 초반 빈 상태도 바로 검토할 수 있기 때문이다.
- QR은 시각 목업이며 실제 스캔 대상이 아니다. 백엔드와 공개 참가 URL이 정해지지 않아 `ava.bakery/join`을 자리표시자로 사용했다.
- 허용된 예외에 따라 오븐 내부만 `--ember`→`--ava` 방사형 발광을 썼다. 그 밖의 면에는 그라데이션이 없다.
- 여섯 번째 색은 추가하지 않았다. 투명도가 필요한 중간톤은 `--ink`와 `--paper`만 혼합했다.

## `/join` 추천안

**C. 참여형**을 추천한다. 해야 할 행동은 큰 버튼 한 번뿐이고, 운영자의 “다 같이” 안내와 짧은 눌림·햅틱이 발행 시작을 공동의 사건으로 만든다. 누른 직후에는 폰의 설명을 늘리지 않고 앞 화면으로 시선을 넘기므로 `/display`의 오븐 진입과 진열 순간도 놓치지 않는다. 다만 운영자가 신호를 주기 어려운 자유 관람형 행사라면 별도 조작이 없는 A가 더 안전하다.

## 만들면서 발견한 문제

- A는 가장 빠르고 시선 이동도 분명하지만, 8초 동안 폰에 진행 근거가 거의 없어 연결이 끊겼다고 오해할 수 있다. `7번 칸`과 “자동 진행 중”을 최소한의 안심 정보로 남겼다.
- B는 무엇이 일어나는지 가장 잘 설명하지만, 네 문장을 차례로 읽는 동안 카드가 TV의 오븐으로 이동한다. 교육 효과와 행사장 클라이맥스가 같은 시선을 두고 경쟁한다.
- C는 A의 비어 있는 기다림을 버튼 한 번으로 의미 있게 바꾸지만 운영자 큐에 의존한다. 햅틱 미지원 기기에서도 눌림과 화면 전환으로 시작 사실을 알 수 있게 했다.
- 공통 완료 화면이 TV 진열과 동시에 뜨면 참가자가 다시 폰으로 고개를 내릴 수 있다. 데모에서는 슬롯 점등 뒤 약 2~3초를 두고 완료 증서를 보여 준다.
- A의 단순함과 B의 정보량 사이 적정점은 “폰에 현재 상태 한 줄, 이유 설명은 교육 세션”에 가깝다. C가 이 균형을 행동으로 가장 잘 보여 준다.

## 공통 구간에서 막힐 가능성이 있는 지점

- 이메일 코드: 메일 앱으로 이동했다 돌아오는 동안 브라우저 상태가 유지되는지, 코드가 늦게 올 때 재전송이 필요한지 실제 로그인 연동 후 확인해야 한다.
- Google 로그인: 목업은 즉시 통과하지만 실제 동의창이 추가되면 30초 목표가 깨질 수 있다.
- 카메라: 권한 거절, 이전에 찍은 사진 선택, 세로 사진의 중앙 크롭을 참가자가 이해하는지 실기기 검증이 필요하다.
- 닉네임: 10자 제한 자체보다 “TV에 공개된다”는 사실을 입력 전에 읽는지가 중요하다. 현재 제목과 설명에서 먼저 알린다.
- 두 동의: 별도 항목이지만 둘 다 확인해야 제출할 수 있다. 특히 `NFT로 공개`와 “나중에 지우기 어렵다”는 문장이 Web3 초심자에게 가장 오래 걸릴 가능성이 크다.
- 최종 제출: `쿠키 보내기` 뒤에는 수정할 수 없다는 의미가 아직 약하다. 실제 정책이 정해지면 재촬영·이름 수정 가능 시점을 명시해야 한다.

## types.ts에 부족한 필드

계약은 수정하지 않았다. 실제 연동 전에 백엔드 담당자와 아래 항목을 논의할 필요가 있다.

- `statusChangedAt` 또는 `mintingStartedAt`: 여러 TV가 동일한 2초 오븐 체류 연출을 재현하려면 서버 기준 시각이 필요하다.
- `submittedAt`: `shelfIndex` 재계산이나 운영 기록에서 제출 순서를 검증할 때 필요하다.
- `failureReason`: TV에는 감추되 향후 `/admin`에서 재시도 판단을 하려면 필요하다.
- 행사명, 실제 `joinUrl`/QR payload, 슬라이드 콘텐츠: 현재 `ShowState`만으로는 행사별 문구와 교육 자료를 내려줄 수 없다.
- 응답 `revision` 또는 `updatedAt`: 1초 폴링 전환 시 오래된 응답이 최신 상태를 덮는 것을 막는 데 유용하다.

## 3안 중 추천

**A. 두꺼운 산세리프 간판**을 추천한다. 3m 거리에서 행사명·상태가 가장 빨리 읽히고, 큰 `--ava` 면이 베이커리 장식보다 Avalanche 브랜드를 먼저 기억하게 한다. B안의 수직 리듬은 상태 라벨에 일부 차용하고, C안의 세리프는 작은 진열 카드에서 읽힘이 떨어져 본 화면에는 쓰지 않았다.

## 오븐과 진열 연출 확인

- 오븐 진입 마지막 230ms에 카드 내부 면을 88%까지 줄이고, 진열장 이동 720ms 동안 원래 크기로 되돌린다.
- MINTING 중에는 오븐 발광과 열기 세로선만 반복하며, 최소 체류는 목업 스토어의 기존 2초 규칙을 그대로 사용한다.
- MINTED 착지 시 해당 슬롯 조명은 180ms 상승, 120ms 유지, 540ms 감쇠해 총 840ms 작동한다.
- 15번째 카드의 슬롯 조명이 끝난 뒤 진열장 외곽 프레임만 1200ms 동안 `--gold`로 한 번 점등한다.

## 2026-08-17 오븐 고정 자리·루트 카피 축약

- 오븐의 네 칸에 `0~3` 고정 주소를 두고, 진입하는 카드에 비어 있는 주소를 배정한다. 한 카드가 진열장으로 떠나도 나머지 카드의 주소와 화면 위치는 바뀌지 않는다.
- 네 칸을 넘는 입력은 화면 밖으로 숨기지 않고 작업대에 남긴다. 고정 칸이 비면 가장 먼저 기다리던 카드 하나만 작업대에서 그 빈칸으로 이동하며, 이미 오븐에 있던 카드는 움직이지 않는다.
- 루트에서 행사 설명, 기능 칩, 참가자 안별 설명을 제거했다. `A/B 데모`를 큰 실행 면으로 두고 A·B·C·TV는 같은 크기의 직접 진입 버튼 네 개로 정리해, 데스크톱에서 주요 문구가 임의 줄바꿈되지 않게 했다.

## 2026-08-17 루트 화면 밀도 재조정 시도

- 직전 축약안은 읽을 문장은 줄였지만 베이커리의 생산 흐름과 화면별 차이까지 사라져 단순한 링크 런처처럼 보였다.
- 왼쪽 5×3 진열장 축약 도형과 `PHONE → OVEN → TV` 장치 도형을 시도했으나, 사용자가 요청한 밀도는 삽화 추가가 아니었으므로 다음 수정에서 모두 제거했다.
- A/B/C/TV 바로가기는 같은 크기를 유지하고 `앞 화면 중심 / 과정 확인 / 함께 시작 / 전체 진열` 한 줄만 복원했다. 긴 설명 문단과 기능 칩은 다시 넣지 않았다.

## 2026-08-17 도형 제거·오븐 5명 초과 처리

- 루트의 미니 진열장과 PHONE/OVEN/TV 도형을 모두 제거했다. 대신 A와 B의 차이 두 줄, 참가 인원과 관찰 화면 정보를 타이포와 구분선만으로 정리했다.
- 빈 오븐 칸에 표시하던 `--paper` 18% 테두리를 제거했다. 빈칸은 별도 윤곽 없이 오븐 내부 면으로만 보인다.
- 오븐 수용량을 4장으로 고정했다. 다섯 번째 `to-oven` 이동은 빈 슬롯이 생길 때까지 시작하지 않으며, 카드가 작업대에 계속 보여 갑자기 사라지지 않는다.
- 5명 동시 입력 슬롯 검증: 1~4번은 각각 `0, 1, 2, 3`번 칸을 유지하고 5번은 대기했다. 2번이 나간 뒤 5번만 빈 `1`번 칸에 배정됐으며 1·3·4번의 슬롯 값은 바뀌지 않았다. `lint`와 프로덕션 빌드도 통과했다.

## 2026-08-17 데모 조작 명칭 정리

- `휴대폰 / TV / 세션`은 서로 같은 종류의 탭처럼 보이지만, `세션`만 여러 명령을 여는 메뉴라 역할을 예측하기 어려웠다.
- `휴대폰 / TV`는 `관찰 화면` 선택으로 유지하고, 구분선 뒤의 별도 `데모 조작` 버튼으로 메뉴를 분리했다.
- 메뉴 안에서는 `참가자 보기`와 `재생`을 나눴다. `이전 사람 / 정지 / 처음 / 설정`은 각각 `이전 참가자 / 일시정지 / 처음부터 / 조건 바꾸기`처럼 실행 결과가 드러나는 문구로 바꿨다.
- Impeccable `clarify` 기준으로 문구와 정보 구조를 점검했으며, 변경 파일에 대한 detector 결과는 위반 0건이다. 프로젝트 런타임 패키지는 추가하지 않았다.

## 2026-08-17 Impeccable 전체 UI/UX 재구조화

- 제품 맥락을 `PRODUCT.md`에 고정했다. 참가자·행사장 관객·팀 리뷰어의 서로 다른 사용 거리와 목적을 앞으로의 화면 판단 기준으로 사용한다.
- 메인에서 `A/B 데모`, `15 COOKIES · ONE SESSION`, 영문 내부 라벨을 제거했다. 메인은 `Avalanche Bakery 이야기 → 행사 흐름 체험 → 참가자 화면 → 행사장 TV`의 제품 입구로만 사용한다.
- A/B 비교는 `/demo`를 연 뒤에만 나타난다. 설정은 `참가 경험 / 사진 제출 간격 / 참가 인원` 순서이며 각 선택이 바꾸는 결과를 바로 설명한다.
- 데모 실행 중 `참가자 폰 / 행사장 TV`는 관찰 화면 선택으로, 참가자 이동·재생·초기화·조건 변경은 `데모 조작`으로 분리했다. 폰에서 조작 메뉴를 열면 하단 바가 인라인으로 교체되어 휴대폰 화면을 가리지 않는다.
- `/join`의 단계별 작은 머리말과 제출 후 반복 상태 라벨을 제거했다. 사진을 고른 뒤에는 `카메라 열기`가 `다시 찍기`로 바뀌어 두 개의 주 버튼이 경쟁하지 않는다.
- 입력 placeholder, 로그인 구분 문구, TV 빈 선반 번호의 대비를 높이고 카메라 입력 포커스 링, 인원 1/15 경계 비활성화, 상태 라이브 영역을 추가했다.
- Firefox CLI 캡처는 SWGL 프레임버퍼 오류로 실패했지만 geckodriver WebDriver로 홈 1600px, 데모 설정·폰·TV, 참가자 화면, TV 1920px를 캡처해 두 차례 검토했다.
- Impeccable detector는 금색 증서 제본선과 참여형 오븐 버튼을 경고했다. 오븐 버튼은 눌림을 유지하는 단일 inset shadow로 교체했고, 금색 제본선은 `DESIGN.md`에 고정된 완료 상태 표현이라 유지했다.
- 독립 마감 리뷰 결과는 `해결 4 / 부분 해결 0 / 미해결 0`이다. `npm run lint`와 `npm run build`를 통과했으며 이번 작업은 요청대로 push·Vercel 배포하지 않는다.
