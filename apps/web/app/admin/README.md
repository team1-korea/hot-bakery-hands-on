# 운영자 화면 (`/admin`)

행사 당일 운영진이 노트북으로 여는 화면입니다. **화면과 API를 같은 사람이 만듭니다**
(백엔드 담당). 참가자 화면·TV 화면과는 담당이 다릅니다 — [AGENTS.md](../../../../AGENTS.md)의
담당 경계를 보세요.

| 찾는 것 | 문서 |
|---|---|
| 엔드포인트 계약 | [API_REFERENCE.md](../../../../API_REFERENCE.md) 「운영자」 절 |
| 상태 전이·실패 복구 | [PIPELINE.md](../../../../PIPELINE.md) |
| 테이블·컬럼 | [apps/web/db/README.md](../../db/README.md) |

---

## 이 화면이 존재하는 이유

**행사는 한 번뿐이고, 14명 중 1명이 증서를 못 받으면 그 사람에게는 100% 실패입니다.**

참가자 화면이 잘 돌면 운영자는 할 일이 없습니다. 이 화면은 **잘 안 될 때를 위한 것**입니다.
그래서 모든 기능이 "막힌 사람을 어떻게 풀어주나"에 맞춰져 있습니다.

그리고 **참가자에게 알릴 수단이 우리에게 없습니다.** Privy가 이메일을 갖고 있고 우리는 메일을
보낼 수 없습니다. 무엇이 잘못됐는지 아는 사람은 이 화면을 보는 운영자뿐이고, 알려주는 것도
운영자가 직접 해야 합니다.

---

## 행사 당일 운영자가 겪는 일

### 1. 명단을 본다

참가자가 QR을 찍고 구글 로그인 + 닉네임을 넣으면 **그 순간 명단에 뜹니다.** 사진은 아직
없습니다(`JOINED`). 시간이 지나며 굽는 중 → 진열 완료로 갈리고, 일부는 실패합니다.

### 2. "저 사진이 안 올라가요"

참가자가 손을 듭니다. 폰이 이상하거나, 와이파이가 죽었거나, 브라우저가 사진 형식을 못 읽거나.

운영자는 명단에서 **닉네임으로 그 사람을 찾습니다.** 이미 등록돼 있으므로 지갑 주소가 서버에
있습니다. 사진은 텔레그램이든 에어드랍이든 운영자 폰으로 다시 찍든 **어떻게든 손에 넣어서**,
그 카드에 대신 올립니다. 그러면 파이프라인이 정상으로 돕니다.

**등록을 로그인 시점으로 앞당긴 이유가 이것입니다.** 제출 시점에 행을 만들면 이 사람은 서버에
존재조차 하지 않아 손쓸 방법이 없습니다.

### 3. "민팅 실패"

**여기가 제일 중요합니다. 이유에 따라 할 일이 완전히 다릅니다.**

| 왜 실패했나 | 할 일 |
|---|---|
| IPFS 업로드 실패 | 재시도. 대개 일시적 |
| 민터 지갑 가스 부족 | Faucet에서 AVAX 채우고 재시도 |
| RPC 오류 | 잠깐 뒤 재시도 |
| **`AlreadyIssued`** | ⚠️ **이미 발행된 것.** 서버가 이벤트를 조회해 복구해야 함 |
| 사진 자체가 문제 | 재시도 소용없음. **새 사진을 받아 대리 업로드** |

그래서 **실패 사유가 화면에 보여야 합니다.** 안 보이면 운영자가 무엇을 눌러야 할지 고를 수
없습니다.

### 4. 이상한 카드를 TV에서 내린다

되돌릴 수 있어야 합니다.

### 5. 로그인만 하고 사라진 사람

등록만 하고 쿠키 만들러 가버린 사람의 카드가 작업대에 남습니다. 10분쯤 뒤 스위퍼가 자동으로
내립니다. **그래도 운영자 명단에는 계속 보여야 합니다** — 나중에 사진을 가져오면 다시 올려야
하니까요.

### 6. TV 화면을 제어한다

접수 중에는 QR 켜기, 발표 시간에는 GALLERY로 전환, 진열장이 15칸을 넘으면 쪽 넘기기.

### 7. 행사 끝 무렵 점검

14명 중 아직 못 받은 사람을 찾아 **직접 불러서 알려줍니다.**

## 구현된 기능

| 기능 | 계약·동작 |
|---|---|
| 운영자 명단 | `GET /api/admin/state` 1초 폴링. 실패 사유·지갑·자동 내림·수정 가능 여부 포함 |
| 상태 확인 | `JOINED` 배지, 미완료/실패 필터, 닉네임 검색, 사진 확대 |
| 복구 | 숨김/복원, 단계별 재시도, `JOINED`·`FAILED` 대리 사진 업로드 |
| 닉네임 수정 | `nicknameEditable`인 카드만 연필 표시, `PATCH /api/admin/entries/{id}` |
| TV 제어 | QR, LIVE/GALLERY, 진열장 페이지 |
| 테스트 초기화 | `capabilities.resetDatabase`가 true일 때만 버튼 표시, 확인 문구 입력 후 실행 |
| 실행 모드 표시 | `capabilities.mockServer`가 true면 목 서버 배지 |
| 세션 | 로그인 상태 확인, 만료 시 로그인 화면 복귀, 로그아웃 |

프론트는 `ALLOW_DB_RESET`이나 `DATABASE_URL`을 직접 추측하지 않습니다. 서버가 내려주는
`capabilities`가 UI의 유일한 기준입니다.

## 닉네임 수정

오타로 등록한 사람을 고쳐 줍니다. **`PINNED` 전에만 됩니다.**

닉네임은 메타데이터 JSON의 `name`과 `attributes`에 들어가고, 그 JSON은 `PINNED` 단계에서
IPFS에 올라갑니다. 컨트랙트에 **메타데이터 수정 함수가 없으므로**, 핀이 끝난 뒤에는 화면의
글자만 바뀌고 증서는 옛 닉네임으로 영구히 남습니다. 그게 더 나쁩니다 — 운영자는 고쳤다고
믿는데 실제로는 안 고쳐진 것이니까요.

| 상태 | 수정 |
|---|---|
| `JOINED` · `SUBMITTED` | 가능 |
| `PINNED` 이후 | **불가.** 서버가 `409`로 거절합니다 |
| `FAILED` | 어디서 실패했는지에 달렸습니다. `metadata_cid`가 비어 있으면 가능 |

화면은 `nicknameEditable`이 true인 카드에만 연필을 보여 줍니다. 최종 판정은 서버가
`metadata_cid is null`로 다시 확인합니다.

## 테스트 데이터 초기화

행사 준비 중에는 만들었다 지웠다를 반복합니다. 매번 SQL Editor에 들어가는 것보다 화면에
버튼이 있는 편이 낫습니다.

> ⚠️ **행사 당일 이 버튼이 존재하면 안 됩니다.** 운영자가 실수로 누르면 그 시점까지의 참가자
> 카드가 전부 사라집니다. 이미 발행된 증서는 체인에 남지만 진열장은 비고, `shelfIndex`가
> 재배정되면서 순서도 뒤섞입니다.

그래서 **환경변수로 잠급니다.**

- `ALLOW_DB_RESET=1`이 있을 때만 엔드포인트가 살아 있고 버튼이 보입니다.
- 운영 배포(Vercel)에는 이 변수를 **넣지 않습니다.** 그러면 버튼 자체가 렌더되지 않고,
  누가 엔드포인트를 직접 때려도 `404`입니다.
- 화면에서는 확인 문구를 타이핑해야 실행됩니다. 클릭 한 번으로는 안 됩니다.

지우는 것: `participants`(cascade로 `entries`까지), 저장된 이미지, `show_state`를 초기값으로.

**지워지지 않는 것** — 이건 버튼이 할 수 있는 일이 아니고, 화면에도 적어 두세요.

| | |
|---|---|
| IPFS에 핀된 것 | 되돌릴 수 없습니다 |
| **체인에 발행된 증서** | 되돌릴 수 없고, **그 지갑 주소는 영구히 사용 불가**입니다 |

`hasBeenIssued(address)`는 소각한 뒤에도 `true`로 남습니다. 그래서 **테스트 민팅은 매번 새
주소로** 하세요. 운영진 지갑으로 테스트하면 행사 당일 그 사람은 증서를 받지 못합니다.

## ⚠️ 대리 업로드에서 반드시 지킬 것

**프레임 합성을 운영자 화면에서도 해야 합니다.**

서버는 이미지를 다시 그리지 않습니다([DECISIONS.md](../../../../DECISIONS.md)). 참가자 화면이
브라우저에서 합성해 보내기 때문입니다. 운영자가 원본 사진을 고르면 **같은 합성을 거쳐서**
보내야 합니다. 안 그러면 프레임 없는 증서가 IPFS에 올라가고 체인에 박힙니다.

`lib/photo.ts`를 재사용하세요. 참가자 화면 담당이 프레임 합성을 그 파일에 공용으로 넣기로
돼 있습니다.

**자르기 UI는 만들지 마세요.** 참가자용 `PhotoCropper`는 손가락으로 맞추는 화면인데, 운영자는
급한 상황에서 씁니다. **정중앙 정사각 자동 자르기**로 끝내세요.

## 하지 말 것

- **`GET /api/state`(공개)에 `failureReason`이나 지갑 주소를 넣어 해결하지 마세요.** 인증 없는
  엔드포인트라 TV URL을 아는 사람이면 누구나 봅니다. 운영자용 조회를 따로 씁니다.
- **카드 표시는 `hidden` 조작만 사용하세요.** 서버가 운영자 숨김과 표시 고정 마커를 함께
  갱신해, 늦은 제출과 스위퍼가 운영자 판단을 뒤집지 않게 합니다.
- **`AlreadyIssued` 판단을 운영자에게 넘기지 마세요.** 재시도 버튼 하나로 두고, 서버가
  이벤트를 조회해 복구합니다. 운영자가 오류 문자열을 읽고 고르게 하면 행사 당일 실수합니다.
- **`FAILED` 건에 새 사진을 올릴 때 CID를 그대로 두지 마세요.** 옛 이미지의 CID로 민팅됩니다.
  (서버 쪽 책임이지만 화면이 이 흐름을 만듭니다.)

## 인증

`bakery_operator` 쿠키(httpOnly). `OperatorGate.tsx`가 막습니다.

> **TV 브라우저에도 운영자 로그인이 필요합니다.** TV의 진열장 페이저가
> `PATCH /api/admin/show`를 부릅니다. 행사 당일 TV를 켜기 전에 그 브라우저에서 `/admin`
> 로그인을 먼저 하세요.

> ⚠️ 운영자 비밀번호에 **시도 횟수 제한이 없습니다.** 대리 업로드가 생기면서 위험이 커졌습니다
> — 이 화면을 잡으면 아무 참가자에게 아무 사진이나 붙일 수 있습니다. 행사 전에
> `OPERATOR_PASSCODE`를 길게 바꾸세요.
