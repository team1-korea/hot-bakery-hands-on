# NFT 교육 세션 진행 가이드

참가자들의 발행이 끝난 직후, 진열장에 보이는 결과를 방금 일어난 기술과 연결하는 7분짜리
세션입니다. 화면의 문장을 읽는 발표가 아니라, 참가자가 한 행동과 체인에 남은 결과 사이를
설명하는 데 초점을 둡니다.

## 시작 전

1. TV 브라우저에서 `/admin` 로그인을 마칩니다.
2. 아직 못 받은 참가자와 실패 건을 먼저 확인합니다.
3. 운영자 화면에서 `진열장만 크게`를 켭니다.
4. 진열장이 두 쪽이면 앞·뒤 쪽을 모두 보여 줍니다.
5. TV에서 `교육 세션 시작`을 누르거나 `S` 키를 누릅니다.

교육 화면은 TV 브라우저 안에서만 바뀝니다. `ShowState`와 운영자 API에는 교육 모드를
추가하지 않았으므로 다른 브라우저의 TV까지 원격으로 바꾸지는 않습니다.

## 조작

| 조작 | 동작 |
|---|---|
| `S` | GALLERY 화면에서 교육 세션 시작 |
| `←` · `PageUp` | 이전 슬라이드 |
| `→` · `PageDown` · `Space` | 다음 슬라이드 |
| `Home` · `End` | 첫 장 · 마지막 장 |
| `Esc` | 진열장으로 돌아가기 |

마지막 장의 `진열장으로 돌아가기` 버튼으로도 종료할 수 있습니다.

## 슬라이드별 진행

### 1. 방금, 쿠키가 NFT가 되었습니다 — 30초

“진열장에 보이는 사진 한 장이 곧 NFT 전부일까요?”라고 먼저 묻습니다. 참가자들이 만든
결과를 이미지, 메타데이터, 체인 기록으로 나눠 보겠다고 예고합니다.

### 2. NFT 한 장은 세 겹으로 이루어집니다 — 60초

- **증서 이미지:** 쿠키 사진과 프레임을 합친 눈에 보이는 결과입니다.
- **메타데이터:** 증서 이름, 설명, 이미지 CID, 닉네임, 행사, 발행일을 담은 JSON입니다.
- **토큰:** C-Chain의 ERC-721 컨트랙트가 `tokenId`, 소유 주소, `tokenURI`를 연결합니다.

이미지 파일 자체가 블록체인 안에 들어가는 것은 아니라고 짚습니다.

### 3. 사진은 체인 안이 아니라 IPFS에 있습니다 — 70초

원본 사진은 참가자 브라우저에서 자르고 프레임을 합칠 때만 쓰이며 서버로 전송되지 않습니다.
서버가 받는 것은 최종 합성 증서 한 장입니다. 이 합성본은 행사 운영을 위해 Supabase Storage에
보관되고, 같은 바이트가 Pinata를 통해 IPFS에 핀됩니다. 이미지와 메타데이터는 각각 CID를
받으며, 체인에는 메타데이터의 `ipfs://` 주소가 들어갑니다.

운영 서비스와 Supabase 데이터는 행사 종료 30일 후 내립니다. “IPFS니까 무조건 영원히
다운로드된다”라고 약속하지 말고, **내용으로 주소를 정하며 현재 Pinata에 고정돼 있다**고
설명합니다.

### 4. Google 로그인 뒤, 내 지갑이 만들어졌습니다 — 60초

Privy가 Google 로그인과 연결된 임베디드 EVM 지갑을 만들었습니다. 백엔드는 참가자가 보내 준
주소를 믿지 않고 Privy 토큰을 검증한 뒤 서버 API로 그 지갑 주소를 조회했습니다.
`ownerOf(tokenId)`가 가리키는 주소가 바로 그 참가자 지갑입니다.

Google은 로그인 수단이고, 서버 민터는 발행 권한만 사용합니다. 둘 다 참가증서의 소유자가
아닙니다. 참가자의 개인키도 우리 서버에 저장하지 않습니다.

### 5. 오븐 안에서는 다섯 단계가 지나갔습니다 — 70초

1. 브라우저가 최종 합성 증서를 제출했습니다.
2. 서버가 이미지와 메타데이터를 IPFS에 핀했습니다.
3. 서버 민터가 참가자 주소와 `ipfs://<metadata CID>`로 `mint`를 호출했습니다.
4. C-Chain 영수증 성공과 `CertificateIssued` 이벤트를 확인했습니다.
5. 서버가 `tokenId`와 `txHash`를 저장해 카드를 진열장으로 옮겼습니다.

이 과정은 배치가 아니라 참가자마다 즉시, 한 번에 한 명씩 직렬로 실행됩니다.

### 6. 이번 참가증서는 팔 수 없는 NFT입니다 — 60초

일반적인 NFT와 마찬가지로 ERC-721의 `tokenId`, `ownerOf`, `tokenURI`를 사용합니다.
차이는 목적과 전송 규칙입니다. 이번 컨트랙트는 EIP-5192 `locked`를 구현해 전송과 승인을
거절하는 소울바운드 참가증서입니다. 한 지갑에는 일반 발행 한 장만 가능하고 전송은 항상
막혀 있습니다. 오발급 복구는 기존 토큰을 `adminBurn`한 뒤 새 tokenId로 `reissue`합니다.

Fuji 테스트넷 증서이므로 투자 상품이나 거래 가능한 자산처럼 설명하지 않습니다.

### 7. C-Chain에는 소유와 발행 기록이 남습니다 — 70초

- 네트워크: Avalanche Fuji C-Chain, Chain ID `43113`
- 컨트랙트: `0x67Ce0bb25ee58B6D000d209B051b9E846D0d6b36`
- 기록: 토큰 ID, 소유 지갑, 메타데이터 URI, 발행 트랜잭션과 이벤트
- 직접 기록하지 않은 것: 원본 사진, 이미지 바이트, 참가자 개인키

원하면 진열장으로 돌아가 카드 한 장의 Explorer 링크를 열고 `CertificateIssued` 거래를 직접
보여 줍니다.

## 여섯 질문에 대한 한 문장 답

1. **NFT 구성:** 증서 이미지, 메타데이터 JSON, C-Chain의 ERC-721 소유 기록이 연결된 것입니다.
2. **사진 저장:** 원본은 브라우저에만 있고, 최종 합성 증서는 운영 저장소와 IPFS에 보관됩니다.
3. **지갑 소유:** Privy가 Google 로그인과 연결해 만든 참가자 임베디드 지갑의 것입니다.
4. **발행 방식:** 서버 민터가 참가자마다 즉시 `mint`하고 영수증과 이벤트까지 확인합니다.
5. **일반 NFT와 차이:** ERC-721이지만 전송할 수 없는 소울바운드 참가증서입니다.
6. **C-Chain 기록:** Fuji에 토큰 ID, 소유 주소, 메타데이터 URI와 발행 거래가 남습니다.

## 피해야 할 표현

- “쿠키 사진을 블록체인에 올렸다” → 이미지는 IPFS, 체인에는 URI가 기록됩니다.
- “Google 지갑이다” → Google은 로그인 수단이고 지갑은 Privy 임베디드 EOA입니다.
- “서버가 참가자의 NFT를 가지고 있다” → 서버는 발행만 하며 소유 주소는 참가자 지갑입니다.
- “메인넷 NFT다” → 현재 배포는 Fuji 테스트넷입니다.
- “NFT니까 사고팔 수 있다” → 이 컨트랙트는 전송과 승인을 막습니다.
