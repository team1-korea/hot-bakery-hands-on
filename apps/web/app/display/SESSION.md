# NFT 교육 세션 진행 가이드

참가자들의 발행이 끝난 직후, 진열장에 보이는 결과를 방금 일어난 기술과 연결하는 약 7분짜리
세션입니다. 화면의 문장을 그대로 읽기보다, 참가자가 한 행동과 체인에 남은 결과 사이를
설명하는 데 초점을 둡니다.

## 시작 전

1. TV 브라우저에서 `/admin` 로그인을 마칩니다.
2. 아직 못 받은 참가자와 실패 건을 먼저 확인합니다.
3. 진열장이 두 쪽이면 앞·뒤 쪽을 모두 보여 줍니다.
4. 마지막 진열장 쪽의 `NEXT` 버튼을 누릅니다. 작업대와 오븐이 보이는 `LIVE` 화면에서도
   바로 시작할 수 있습니다.

교육 화면은 TV 브라우저 안에서만 바뀝니다. `ShowState`와 운영자 API에는 교육 모드를
추가하지 않았으므로 다른 브라우저의 TV까지 원격으로 바꾸지는 않습니다.

## 조작

| 조작 | 동작 |
|---|---|
| `←` · `PageUp` | 이전 슬라이드 |
| `→` · `PageDown` · `Space` | 다음 슬라이드 |
| `Home` · `End` | 첫 장 · 마지막 장 |
| `Esc` | 진열장으로 돌아가기 |

마지막 장의 `진열장으로 돌아가기` 버튼으로도 종료할 수 있습니다.

## 슬라이드별 진행

### 1. 내 쿠키 사진이, 내 지갑의 참가증서가 되었습니다 — 25초

“사진 파일 하나가 NFT로 바뀐 걸까요?”라고 먼저 묻습니다. 실제로는 완성된 증서 이미지,
그 이미지를 설명하는 메타데이터, 참가자 지갑의 소유 기록이 서로 연결됐다고 예고합니다.

### 2. NFT는 세 가지가 연결된 하나의 기록입니다 — 50초

- **증서 이미지:** 쿠키 사진과 프레임을 합친 눈에 보이는 JPEG입니다.
- **메타데이터:** 증서 이름, 설명, 이미지 CID, 닉네임과 행사 정보를 담은 JSON입니다.
- **토큰:** C-Chain의 ERC-721 컨트랙트가 `tokenId`, 소유 주소, `tokenURI`를 연결합니다.

셋 중 어느 하나만 NFT 전부라고 말하면 정확하지 않다고 설명합니다.

### 3. 사진은 IPFS에, 소유 기록은 C-Chain에 남습니다 — 60초

원본 사진은 참가자 브라우저에서 자르고 프레임을 합칠 때만 쓰이며 서버로 전송되지 않습니다.
서버가 받는 것은 최종 합성 증서 한 장입니다. 같은 합성본을 행사 운영용 Storage에 보관하고,
Pinata를 통해 IPFS에 핀합니다. 이미지와 메타데이터는 각각 CID를 받으며 체인에는 메타데이터의
`ipfs://` 주소가 들어갑니다.

운영 서비스와 Supabase 데이터는 행사 종료 30일 후 내립니다. “IPFS니까 무조건 영원히
다운로드된다”라고 약속하지 말고, **내용으로 주소를 정하며 현재 Pinata에 고정돼 있다**고
설명합니다.

### 4. Google은 로그인 수단, 지갑 주소가 실제 소유자입니다 — 50초

Privy가 Google 로그인과 연결된 임베디드 EVM 지갑을 만들었습니다. 백엔드는 참가자가 보내 준
주소를 믿지 않고 Privy 토큰을 검증한 뒤 서버 API로 그 지갑 주소를 조회했습니다.
`ownerOf(tokenId)`가 가리키는 주소가 바로 참가자 지갑입니다.

Google은 로그인 수단이고, 서버 민터는 발행 권한만 사용합니다. 둘 다 참가증서의 소유자가
아닙니다. 참가자의 개인키도 우리 서버에 저장하지 않습니다.

### 5. 제출한 뒤, 한 사람씩 즉시 발행했습니다 — 55초

1. 브라우저가 최종 합성 증서를 제출했습니다.
2. 서버가 이미지와 메타데이터를 IPFS에 핀했습니다.
3. 서버 민터가 참가자 주소와 `ipfs://<metadata CID>`로 `mint`를 호출했습니다.
4. C-Chain 영수증 성공과 `CertificateIssued` 이벤트를 확인했습니다.
5. 서버가 `tokenId`와 `txHash`를 저장해 카드를 진열장으로 옮겼습니다.

이 과정은 배치가 아니라 참가자마다 즉시, 한 번에 한 명씩 직렬로 실행됩니다.

### 6. ERC-721 규격 위에, 전송 잠금 규칙을 더했습니다 — 70초

ERC-721은 NFT마다 `tokenId`라는 고유 번호를 붙이고, `ownerOf`로 소유 지갑을,
`tokenURI`로 이미지와 메타데이터 주소를 읽게 하는 공통 규격입니다. 이 규격을 사용하기 때문에
Avalanche Explorer와 Core Wallet 같은 표준 도구가 참가증서를 인식할 수 있습니다.

이번 컨트랙트에는 여기에 세 가지 규칙을 더했습니다.

1. EIP-5192 `locked`가 항상 참이며 전송과 승인 요청을 모두 거절합니다.
2. 처음 발행하는 참가증서는 한 지갑에 한 장으로 제한합니다.
3. 오발급은 운영자가 기존 토큰을 `adminBurn`한 뒤 새 tokenId로 `reissue`합니다.

네트워크와 무관하게 전송이 잠긴 참가증서이므로 투자 상품이나 거래 가능한 자산처럼 설명하지
않습니다.

### 7. 행사 뒤에는 Core에서 같은 지갑을 열 수 있습니다 — 65초

행사 후 Google 로그인에 사용한 이메일로 Core Wallet 관리 가이드를 보냅니다. 참가자가 Privy
임베디드 지갑의 개인키를 직접 내보내 Core의 `Import Private Key`로 가져오면, 새 지갑으로 NFT를
전송하는 것이 아니라 **같은 지갑 주소를 Core에서도 여는 것**입니다.

1. Privy에서 본인 인증 뒤 개인키를 내보냅니다.
2. 본인 기기의 Core에서 개인키로 계정을 가져옵니다.
3. Privy와 Core에 같은 주소가 나타나는지 확인합니다.

개인키는 지갑 소유권 자체입니다. 운영자에게 보내지 않고 링크·메신저·공용 PC에 입력하지 않도록
강조합니다.

- [Privy 지갑 내보내기](https://docs.privy.io/wallets/wallets/export)
- [Core Wallet 계정 가져오기](https://support.core.app/en/articles/6821877-core-extension-how-can-i-import-an-account)

### 8. 발행 기록은 공개되고, 개인키는 공개되지 않습니다 — 50초

- 네트워크: 슬라이드에 표시된 현재 C-Chain과 Chain ID(리허설 `43113`, 행사 `43114`)
- 컨트랙트: 현재 네트워크의 Avalanche Bakery Certificate
- **C-Chain 공개 기록:** 토큰 ID, 소유 주소, 메타데이터 URI, 발행 트랜잭션과 이벤트
- **IPFS 공개 파일:** 현재 핀된 최종 참가증서 JPEG와 메타데이터 JSON
- **수집하지 않거나 공개하지 않은 정보:** 원본 사진, Google 계정, 참가자 개인키

원본 사진과 최종 참가증서를 구분해야 합니다. 원본 사진은 서버에 오지 않지만, 참가자가 확인한
최종 합성 증서는 NFT를 표시할 수 있도록 IPFS에서 공개적으로 읽을 수 있습니다. 슬라이드의
`#8`, 축약 지갑 주소와 거래 성공 표시는 구조를 설명하는 예시이며, 실제 기록은 진열장 카드의
Explorer 링크를 열어 확인합니다.

## 일곱 질문에 대한 한 문장 답

1. **NFT 구성:** 증서 이미지, 메타데이터 JSON, C-Chain의 ERC-721 소유 기록이 연결된 것입니다.
2. **사진 저장:** 원본은 브라우저에만 있고, 최종 합성 증서는 운영 저장소와 IPFS에 보관됩니다.
3. **지갑 소유:** Privy가 Google 로그인과 연결해 만든 참가자 임베디드 지갑의 것입니다.
4. **발행 방식:** 서버 민터가 참가자마다 즉시 `mint`하고 영수증과 이벤트까지 확인합니다.
5. **일반 NFT와 차이:** ERC-721 규격을 사용하지만 EIP-5192로 전송과 승인을 막은 참가증서입니다.
6. **Core 관리:** 개인키를 Core에 가져와 NFT 전송 없이 같은 지갑 주소를 엽니다.
7. **C-Chain 기록:** 현재 설정된 C-Chain에 토큰 ID, 소유 주소, 메타데이터 URI와 발행 거래가 남습니다.

## 피해야 할 표현

- “쿠키 사진을 블록체인에 올렸다” → 이미지는 IPFS, 체인에는 URI가 기록됩니다.
- “Google 지갑이다” → Google은 로그인 수단이고 지갑은 Privy 임베디드 EOA입니다.
- “NFT를 Core Wallet으로 전송한다” → Privy 지갑의 개인키를 Core에 가져와 같은 주소를 여는 것입니다.
- “서버가 참가자의 NFT를 가지고 있다” → 서버는 발행만 하며 소유 주소는 참가자 지갑입니다.
- “메인넷이니 거래할 수 있다” → 네트워크와 무관하게 이 증서는 전송이 잠겨 있습니다.
- “NFT니까 사고팔 수 있다” → 이 컨트랙트는 전송과 승인을 막습니다.
